# 🛒 רשימת קניות

אתר רשימת קניות בעיצוב כהה ו-RTL, מותאם לטלפון. **בלי שרת**: הרשימה יושבת בשני קבצי TXT בריפו של GitHub,
והאתר קורא וכותב אליהם דרך ה-API של GitHub.

## שני הקבצים

**`shopping_list.txt`** – מה לקנות עכשיו (כמות לכל מוצר, ו-✓ למה שכבר נקנה):

```
מוצרי חלב: חלב x2, ✓גבינה לבנה, יוגורט x4
ירקות: מלפפון x3, עגבניה x4
```

**`all_items.txt`** – כל הפריטים לפי קטגוריות, ללא כמויות. מכאן בוחרים מה להוסיף לרשימת הקניות:

```
מוצרי חלב: חלב, גבינה לבנה, גבינה צהובה, יוגורט
ירקות: מלפפון, עגבניה, חסה, כרוב, גזר
```

- שורה אחת לכל קטגוריה. שורה שמתחילה ב-`#` היא הערה.
- כמות נכתבת אחרי `x` (`חלב x2`). בלי `x` = 1.
- בעורך, כמות **0** מאפירה את הפריט ומסירה אותו מרשימת הקניות. הוא נשאר ב-`all_items.txt`.

אפשר לערוך את שני הקבצים גם ידנית ב-GitHub (כפתור העיפרון ← Commit), והאתר יציג את השינוי תוך כמה שניות.

## התקנה (פעם אחת)

1. צרו ריפו **ציבורי** והעלו אליו את כל הקבצים.
2. Settings → Pages → Source: *Deploy from a branch* → Branch: `main`, תיקייה `/ (root)`.
3. האתר יעלה ב-`https://<user>.github.io/<repo>/`. הריפו מזוהה אוטומטית מהכתובת.
   (אם האתר מאוחסן במקום אחר, מלאו `GITHUB_REPO` ב-`config.js`.)

## מי יכול לעדכן?

| מי | מה יכול |
|---|---|
| כל מי שפותח את הקישור | רואה את הרשימה העדכנית, ומסמן "נקנה" **במכשיר שלו בלבד** |
| מי שמחובר (חשבון GitHub עם הרשאת כתיבה + טוקן) | עורך, משנה כמויות ומסמן – והכול נשמר בקבצים ונראה לכולם |

כדי לאפשר למישהו לעדכן: Settings → Collaborators → Add people. אחר כך הוא לוחץ באתר
**«🔑 התחברות לעדכון»** ומדביק טוקן אישי (פעם אחת בכל מכשיר):

1. [יצירת טוקן](https://github.com/settings/personal-access-tokens/new) (Fine-grained token).
2. **Repository access** ← Only select repositories ← הריפו של הרשימה.
3. **Permissions** ← Repository permissions ← **Contents: Read and write**.
4. Generate, העתקה, הדבקה באתר.

הטוקן נשמר רק בדפדפן של המכשיר, ומוגבל לריפו הזה. אל תתחברו ממחשב משותף. אפשר להתנתק מתוך אותו חלון.

אי אפשר לאפשר עדכון לאנשים בלי חשבון GitHub: כתיבה לקובץ בריפו תמיד דורשת הרשאה.

## איך זה עובד

- סימון ושינוי כמות נשמרים אחרי כ-1.2 שניות, כל השינויים יחד ב-Commit אחד.
- אם שני אנשים משנים בו-זמנית, האתר מושך את הגרסה העדכנית ומחיל עליה את השינוי, ולא דורס אחרים.
- האתר בודק עדכונים כל 20 שניות (`SYNC_INTERVAL_MS`) ובכל חזרה לטאב.
- כל שמירה יוצרת Commit בריפו, אז ההיסטוריה מלאה ואפשר לשחזר גרסה קודמת ב-GitHub.
- אם ה-API של GitHub לא זמין, האתר מציג את עותק הקבצים שמוגש עם האתר, במצב קריאה בלבד.

## למה לא XLSX?

TXT פשוט יותר כאן: קריאה וכתיבה בלי ספרייה, שינויים קריאים ב-Commit, ופתרון התנגשויות לפי שורות.
קובץ XLSX הוא בינארי, ודורש ספריית פענוח, ואי אפשר לראות בו מה השתנה.

## הרצה מקומית

```bash
python -m http.server 8000
```
ואז `http://localhost:8000`. בלי ריפו מוגדר האתר במצב קריאה בלבד ומציג את הקבצים המקומיים.


## יחידות מידה בקובצי TXT

בסוף שם המוצר נשמר סימן יחידת המידה:
- `@` = גרם; כל צעד בכמות הוא 100 גרם.
- `$` = ק״ג; כל צעד בכמות הוא 0.5 ק״ג.
- `%` = יחידה; כל צעד בכמות הוא יחידה אחת.

לדוגמה: `אורז@ x2` הוא 200 גרם, `קמח$ x3` הוא 1.5 ק״ג, ו-`ביצים% x2` הוא 2 יחידות.
מוצרים ישנים ללא סימן יחידה ייחשבו כברירת מחדל ליחידות (`%`).


## תיקון בקרת הכמות
לחצני + ו- מעדכנים את הכמות בצעד של יחידת המידה שנבחרה: 100 גרם (`@`), חצי ק״ג (`$`) או יחידה אחת (`%`). תצוגת הכמות ליד הלחצנים מציגה את הכמות בפועל.
